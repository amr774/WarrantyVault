# Scanner verification

## Real scanned receipt — 2026-10-24

Verified Python health at `127.0.0.1:8100`, the Nest API at `localhost:3101`, and the React browser flow at `localhost:4174`, using the same isolated PostgreSQL database on port 15434. No original database or Docker volume was reset.

The input was the [public SROIE scanned receipt 000.jpg](https://github.com/zzzDavid/ICDAR-2019-SROIE/blob/master/data/img/000.jpg), SHA-256 `8b85d2c325c68579b53446177602709a8f8faeeec710912f62b6ad369234887c`. Its PDF test used a local image-to-PDF conversion of the same real receipt. Neither file contains generated receipt text. No dataset annotations or expected answers were passed into OCR.

- Direct Python inference and authenticated browser → Nest → Python inference succeeded.
- Both JPG and PDF returned 44 text regions, including `KF MODELLING CLAY KIDDY FISH`, `25/12/2018 8:13:39 PM`, and `9.00`. This establishes actual text extraction, not perfect transcription: the store name and some footer characters were misrecognized.
- Found and fixed a parser gap: OCR separated the date label from its timestamp. The service now preserves bounding boxes, and the parser pairs a detached date label only with a single nearby date on the same page and row. Valid timestamp suffixes are supported; ambiguous dates remain blank. Purchase date prefills as `2018-12-25`, marked uncertain for review.
- Merchant, product name, price and currency were **not automatically structured** from this receipt's unlabeled columns. They remain editable, and the original/raw text is available. No warranty was printed; duration and expiration remain blank. The existing required-duration validation prevents saving this sample with unknown coverage.
- Registration and fresh-cookie login, dashboard scan entry, image preview, rendered PDF preview, progress state, raw text, manual edits, missing-field validation, malformed upload errors and 390px layout passed in Playwright. No uncaught browser errors occurred.
- An initial registration failed when Node's API file watcher restarted mid-request (`ECONNRESET`). The isolated resume helper now runs the compiled API without watch mode. Registration/login passed after that change; PostgreSQL was never stopped.
- 15 Python parser/document tests passed, including timestamp validation and rejection of cross-page, cross-row, distant, low-confidence and conflicting date matches.
- Reran `scripts/test-scanner-local.mjs` after the fix: actual English PNG/JPG/WebP/PDF and Arabic PNG/PDF OCR passed with the numeric omissions documented below; reviewed saving, exact original-byte download, cross-user access denial, upload limits and no-auto-save checks passed. The request limiter returned 429 as expected and the test waited before retrying. Two new test products were retained in the isolated database.

Detailed real-receipt outputs, screenshots and the test report are in `.data/real-receipt/`. Repeat with `node scripts/test-scanner-real-receipt.mjs`; setup and browser steps are in [LOCAL_OCR.md](LOCAL_OCR.md). No paid API, API key or external document processing is used. A physical phone camera and a real Arabic receipt have not been tested; Arabic checks below use explicitly synthetic fixtures.
